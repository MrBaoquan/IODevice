# 架构变更说明：源设备配置位置调整

## 变更日期
2025-11-29

## 变更概述
将源设备配置从映射级别提升到协议组级别，使配置更加合理和高效。

## 变更原因
1. **逻辑更合理**：同一协议组下的所有映射通常来自同一个源设备
2. **减少冗余**：避免在每个映射中重复配置相同的源设备
3. **配置更简洁**：减少用户需要配置的步骤
4. **维护更方便**：更改源设备时只需修改协议组配置，无需逐个修改映射

## 变更内容

### 1. 模型层变更

#### ProtocolGroup.cs
- **新增字段**：`SourceDevice` (string)
  - 用于存储协议组的源设备名称
  - 该协议组下的所有映射将从此设备接收输入

#### ActionKeyMapping.cs
- **移除字段**：`SourceDevice`
  - 映射配置不再包含源设备信息
  - 改为使用所属协议组的源设备配置

### 2. DTO层变更

#### ProtocolGroupDto
- **新增属性**：`SourceDevice` (XmlAttribute)

#### MappingDto
- **移除属性**：`SourceDevice`

### 3. ViewModel层变更

#### EventForwardConfigViewModel.cs
- **SaveConfig方法**：保存时将协议组的SourceDevice写入DTO
- **LoadConfig方法**：加载时从DTO读取SourceDevice到协议组
- **AddProtocolGroupCommand**：新建协议组时自动设置默认源设备（第一个可用设备）
- **AddMappingCommand/AddMappingToGroupCommand**：创建映射时不再设置SourceDevice
- **GenerateRangeMappings**：批量生成映射时不再设置SourceDevice

#### RangeMappingDialogViewModel.cs
- **移除字段**：`_sourceDevice`、`SourceDevice` 属性、`AvailableDevices` 集合
- **验证逻辑**：不再验证源设备是否为空

### 4. View层变更

#### EventForwardConfigWindow.axaml
- **协议组配置区域**：
  - 在"协议类型"下方新增"源设备"选择框
  - 显示设备图标和设备名称
  - 说明文字："选择接收键值输入的源设备，该协议组下所有映射将从此设备接收输入"

- **映射详细配置区域**：
  - 移除"源设备"选择框
  - "源Key"输入框位置上移

#### RangeMappingDialog.axaml
- **移除**："源设备配置"整个区块
- **重命名**："源设备配置" → "源配置"

### 5. Service层变更

#### EventForwardingService.cs
- **Start方法重构**：
  ```csharp
  // 变更前：每个映射独立获取设备并绑定
  foreach (var mapping in group.Mappings) {
      var ioDev = IODeviceController.GetIODevice(mapping.SourceDevice);
      // ... 绑定逻辑
  }
  
  // 变更后：协议组级别获取设备，所有映射共享
  if (string.IsNullOrEmpty(group.SourceDevice)) continue;
  var ioDev = IODeviceController.GetIODevice(group.SourceDevice);
  if (ioDev == null) continue;
  
  foreach (var mapping in group.Mappings) {
      // ... 绑定逻辑
  }
  ```

### 6. 文档更新

#### 批量范围映射使用说明.md
- 更新"配置映射参数"章节，移除源设备配置说明
- 添加注意事项："源设备现在在协议组级别配置，不在此对话框中设置"
- 更新所有示例，移除"源设备"行

## 配置文件兼容性

### XML格式变更
```xml
<!-- 变更前 -->
<ProtocolGroup GroupName="测试组" ...>
  <Mappings>
    <Mapping SourceDevice="ExtDev" SourceKey="Button_00" .../>
    <Mapping SourceDevice="ExtDev" SourceKey="Button_01" .../>
  </Mappings>
</ProtocolGroup>

<!-- 变更后 -->
<ProtocolGroup GroupName="测试组" SourceDevice="ExtDev" ...>
  <Mappings>
    <Mapping SourceKey="Button_00" .../>
    <Mapping SourceKey="Button_01" .../>
  </Mappings>
</ProtocolGroup>
```

### 向后兼容性
- **旧配置文件加载**：可以正常加载，但映射中的SourceDevice信息会被忽略
- **建议**：加载旧配置后，需要为每个协议组手动设置SourceDevice
- **未来改进**：可以考虑添加自动迁移逻辑，从第一个映射的SourceDevice迁移到协议组

## 使用影响

### 用户操作流程变更

#### 创建新配置
1. 创建协议组
2. **在协议组配置中选择源设备**（新增步骤）
3. 添加映射，只需配置源Key和目标Key

#### 批量范围映射
1. 选择协议组
2. 打开批量映射对话框
3. 配置源Key范围和目标Key范围（无需选择源设备）
4. 生成映射

#### 修改源设备
- **变更前**：需要逐个修改每个映射的源设备
- **变更后**：只需在协议组配置中修改一次

## 优势总结

1. ✅ **配置更简洁**：减少重复配置
2. ✅ **逻辑更清晰**：源设备属于协议组的共同属性
3. ✅ **维护更方便**：集中管理源设备配置
4. ✅ **性能更优**：Service层只需获取一次设备实例
5. ✅ **批量操作更快**：范围映射无需重复选择源设备

## 注意事项

1. **旧配置迁移**：加载旧版本配置文件时，需要手动为协议组设置源设备
2. **设备必填**：协议组必须配置源设备，否则该组下的映射不会生效
3. **设备变更影响**：修改协议组的源设备会影响该组下所有映射
4. **设备验证**：在启动转发服务时，会验证协议组的源设备是否存在
